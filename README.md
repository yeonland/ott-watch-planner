# SCENE SIDE

> **작품을 발견하는 새로운 시선**

영화·드라마·애니메이션·영상 시리즈를 **관심사와 주제에 따라 탐색**하고, 발견한 작품과 감상 기록을 모으는 **콘텐츠 아카이브**.

**SCENE SIDE**는 영화관에서 상영작을 고르듯 새로운 작품을 발견하고, 마음에 남은 작품을 필름의 한 장면처럼 보관하는 경험을 지향합니다.

> **프로젝트 상태:** 기획 및 정적 홈 화면 프로토타입 단계. 이 README의 기능 명세는 **구현 목표**이며, 구현 완료 기능과 혼동하지 않습니다.
>
> **원본 저장소:** https://github.com/yeonland/ott-watch-planner  
> 기존 저장소명과 초기 코드의 `Dabom` 표기는 이전 기획의 흔적입니다. **서비스명은 SCENE SIDE로 확정**했고, 저장소명 변경은 별개로 결정합니다.

### 기획 의도

영상 콘텐츠가 다양한 플랫폼에 흩어져 있는 환경에서, 사용자는 작품의 제목을 정확히 모르더라도 특정 시대, 문화, 소재, 분위기 같은 관심사를 통해 새로운 작품을 찾고 싶을 수 있습니다.

SCENE SIDE는 작품명·장르 중심의 검색을 넘어 **주제와 맥락으로 작품을 발견**하도록 돕는 서비스를 목표로 합니다. 발견한 작품을 저장하고 감상 여부와 짧은 기록을 남겨, 탐색 경험이 나만의 아카이브로 자연스럽게 이어지도록 설계합니다.

작품 속 역사·문화적 배경은 작품 이해를 돕는 **짧은 보조 정보**로 제공합니다. 역사 학습, 언어 학습, OTT 구독료 관리 등을 첫 버전에 한꺼번에 넣지 않습니다.

### 서비스 포지셔닝

- **아닌 것:** OTT 요금제 비교·자동 구독 해지 앱, 모든 시청 회차를 세밀하게 관리하는 트래커, 역사/언어 학습 플랫폼
- **지향하는 것:** 취향과 관심사로 작품을 발견하고, 저장하고, 기억을 남기는 시네마형 콘텐츠 아카이브
- **우선순위:** **탐색이 주인공**, 기록은 탐색을 자연스럽게 이어주는 간편한 기능

### 브랜드 문장

**영화관처럼 작품을 발견하고, 필름처럼 나만의 장면을 모은다.**

이 문장은 디자인 콘셉트를 설명하기 위한 카피이며, 공식 부제는 **「작품을 발견하는 새로운 시선」**입니다.

## 2. 타깃 사용자 — 검증 전 가설

### 메인 타깃: 24~34세

영화·드라마·애니메이션·시리즈를 즐겨 보고, 유명 작품 목록만 훑기보다 **주제·분위기·세계관**에 맞는 작품을 찾고 싶어 하는 사용자.

**라이프스타일 가설**

- 퇴근이나 수업 후 OTT에서 작품을 고르는 시간이 있음
- 제목을 모를 때도 “조선 궁중 이야기”, “일본 여름 감성”, “시간여행”처럼 관심사로 탐색함
- 작품을 저장하고 싶지만 긴 감상문이나 세밀한 회차 입력은 부담스러워함
- 포스터·시네마 무드·정돈된 아카이브 UI를 선호할 수 있음
- 모바일에서 빠르게 탐색하고, 필요하면 데스크톱에서 자세히 확인함

### 서브 타깃 가설

- **19~23세:** 취향과 소재 중심의 콘텐츠 발견에 관심 있는 사용자
- **35~42세:** 복잡한 관리 기능 없이 작품을 찾고 저장하려는 사용자

> 연령대·취향·행동 특징은 조사로 검증되지 않은 **기획 가설**입니다. 실제 사용자 테스트를 통해 수정합니다. OTT 구독 개수나 특정 소비 성향을 사실처럼 단정하지 않습니다.

### 핵심 사용 시나리오

1. 사용자가 홈에서 `조선시대` 주제를 선택합니다.
2. 관련 작품 목록을 살펴보고 국가·장르 등으로 좁힙니다.
3. 작품 상세에서 줄거리와 짧은 역사·문화 배경을 확인합니다.
4. 마음에 드는 작품을 **보관함에 저장**합니다.
5. 감상 후 **봤어요 / 별점 / 한 줄 감상**을 선택적으로 남깁니다.

**성공 기준:** 작품 제목을 몰라도 관심사를 통해 작품을 찾고, 복잡한 절차 없이 저장할 수 있어야 합니다.

## 3. 디자인 시스템

### 3-1. 전체 콘셉트: Modern Cinematic Archive

**키워드:** 영화관, 시네마 스크린, 상영작, 포스터, 필름, 장면 수집, 몰입감, 미니멀

- 전체 UI는 **현대적인 영화관**에서 영감을 얻은 차분한 다크 테마를 사용합니다.
- 시선을 끄는 주인공은 **작품 포스터와 탐색 주제**입니다.
- 영화관 티켓의 타이포·번호·구분선은 필요할 때만 보조 요소로 사용합니다.
- **보관함에서만 필름 프레임을 주요 시각 장치**로 사용합니다.
- 우표·우편함·엽서 콘셉트는 **채택하지 않습니다**. 필름과 우표를 혼합해 브랜드를 복잡하게 만들지 않습니다.
- 오래된 영화관을 그대로 재현하기보다는 **세련되고 간결한 영화적 분위기**를 목표로 합니다.

### 3-2. 컬러 팔레트: 4색 + 보관함 전용 1색

| 토큰 | 색상 | 용도 |
| --- | --- | --- |
| Cinema Black | `#171717` | 전체 배경·필름 바탕 |
| Ticket Ivory | `#F5F0E6` | 기본 텍스트·밝은 프레임·중요한 정보 |
| Spotlight Yellow | `#F2C94C` | 브랜드 포인트·주요 버튼·선택 상태 |
| Film Gray | `#858585` | 보조 정보 글자·경계선 |
| Velvet Red | `#A63D40` | **보관함(필름 아카이브) 전용** 포인트 |

```css
:root {
  --color-bg: #171717;
  --color-ivory: #F5F0E6;
  --color-accent: #F2C94C;
  --color-gray: #858585;
  --color-archive: #A63D40; /* 보관함 화면을 만들 때 추가 */
}
```

**사용 원칙**

- 브랜드 주색은 **블랙·아이보리·옐로**이며, 그레이는 보조색입니다.
- 2026-10-22 포인트 컬러를 Velvet Red(`#A63D40`)에서 Spotlight Yellow로 변경했습니다. 빨강은 검정 배경 대비가 약 2.9:1이라 글자로 쓸 수 없었고, 노랑은 약 11:1로 강조 글자에도 쓸 수 있기 때문입니다.
- 노란 배경 위의 글자는 Cinema Black을 사용합니다.
- 이 5색 외에 새 포인트 컬러를 추가하지 않습니다.

**Velvet Red 사용 규칙 (2026-10-22 결정)**

- 탐색은 노란 스포트라이트, 보관함은 빨간 필름으로 구분합니다. "보는 작품은 포스터, 저장한 작품은 필름 아카이브"라는 시각적 차이를 색으로도 드러내기 위함입니다.
- 쓰는 곳: **보관함 화면의 선택 상태와 버튼**(분류 탭, 빈 화면 버튼), `MY FILM ARCHIVE` 라벨 장식, 필름 프레임 번호, **보관된 상태 표시**(상세의 "보관됨" 버튼·배지, 포스터 위 찜 버튼). 보관함 화면 안에서는 노랑 대신 빨강이 선택 색입니다.
- 검정 배경 대비가 약 2.9:1이므로 **글자색으로 쓰지 않습니다.** 빨간 배경 위에는 Ticket Ivory 글자(약 5.5:1)를 쓰거나 장식으로만 사용합니다.
- 보관과 관계없는 화면(홈·탐색)의 일반 선택 상태·주요 버튼은 노랑을 씁니다. 하단 메뉴는 모든 화면 공통이라 노랑을 유지합니다.
- 삭제·경고 표시에 쓰지 않습니다. 브랜드 색이 '위험'이라는 의미와 섞이지 않게 합니다.
- 카드·패널의 명도 차이는 기본색의 투명도/톤 조절로 처리하되, 불필요한 색을 늘리지 않습니다.
- Film Gray `#858585`는 배경 대비 약 4.8:1로 보조 정보 글자에 쓸 수 있습니다. 더 어두운 회색으로 바꾸면 대비를 다시 확인합니다.

### 3-3. 타이포그래피와 컴포넌트

- **로고:** `SCENE SIDE`를 중심으로 한 심플한 워드마크. 첫 버전에는 복잡한 심볼이 필수 아님
- **한글 본문:** Pretendard 또는 시스템 산세리프
- **영문 보조 라벨:** 대문자, 여유 있는 자간 사용 가능 (`NOW SHOWING`, `MY FILM ARCHIVE`, `FRAME 001`)
- **포스터:** 원본 가독성이 최우선. 제목과 필터보다 과도한 장식이 눈에 띄지 않도록 함
- **검색/필터:** 사용성 우선. 영화관 콘셉트 때문에 검색 동작을 어렵게 만들지 않음
- **반응형:** 모바일 우선, 화면이 넓으면 포스터 그리드 확장

### 3-4. 필름 프레임 사용 규칙

**보관함에서** 저장된 작품을 필름의 한 컷처럼 배치합니다.

- 필름 특유의 **검은 테두리, 위·아래 또는 양옆의 구멍, 작은 프레임 번호**를 절제해서 사용
- 작품별 포스터를 틀 안에 넣되, 이미지가 잘리지 않도록 기본 비율과 `object-fit`을 신중히 선택
- 모바일에서는 필름 구멍·테두리가 과밀하지 않게 축소하거나 간소화
- 일반 탐색 결과 목록에 필름 프레임을 반복 적용하지 않음
- 사용자가 보는 작품은 **포스터**, 저장된 작품은 **필름 아카이브**라는 시각적 차이를 만듦
- 실제 필름 애니메이션·복잡한 전환 효과는 MVP 필수 기능이 아님

## 4. 화면 구성 — MVP 4개

### 4-1. 홈 (Home)

**목적:** 영화관 로비에서 상영작을 둘러보듯 탐색을 시작하게 하기

- `SCENE SIDE` 로고 및 부제
- 눈에 띄는 작품 검색창 (작품명·관심 주제)
- `오늘 어떤 이야기를 만나볼까?`와 같은 짧은 메인 카피
- **주제별 진입 카드/태그**: 예) 조선시대, 시간여행, 신화·전설, 일본 여름, 성장 이야기
- 몇 개의 작품 포스터 또는 큐레이션 섹션
- 홈의 탐색 요소는 실제 검색 결과/필터와 연결

**디자인:** 시네마 스크린 같은 몰입감. 하지만 카피·검색·주제 진입이 포스터보다 먼저 이해되도록 배치

### 4-2. 탐색 (Explore)

**목적:** 작품명을 몰라도 주제·관심사로 작품 발견

- 제목/키워드 검색
- 기본 필터: **국가, 장르**
- 차별화 필터: **시대적 배경, 문화적 소재/주제**
- 포스터 그리드와 검색 결과 개수
- 선택된 필터 표시 및 초기화
- 조건에 맞는 결과가 없을 때 안내
- 필터는 처음부터 한 번에 모두 펼치지 않고 모바일에서는 단순하게 정리

**검색 원칙:** 제목에 포함된 글자뿐 아니라 등록한 태그와 연결해, 주제별 탐색이 실제로 작동하도록 함. 초기에는 태그가 잘 정리된 작은 데이터셋으로 검증

### 4-3. 작품 상세 (Detail)

**목적:** 저장 전 작품의 내용과 맥락을 빠르게 이해

- 포스터·제목·유형(영화/드라마/애니메이션/영상 시리즈)·국가·장르
- 짧은 줄거리
- 시대적 배경·문화적 소재 태그
- **짧은 역사·문화 배경 설명** (준비된 작품에만 표시, 가능하면 출처 명시)
- **보관하기 / 봤어요** 동작
- 선택적으로 별점과 한 줄 감상

**주의:** 학습 코스·퀴즈·언어 학습 등 별도 기능으로 확장하지 않음

### 4-4. 보관함 (My Film Archive)

**목적:** 찾은 작품을 필름 한 컷처럼 모아두고 간단하게 기록

- 전체 / 보고 싶은 작품 / 본 작품 필터
- **필름 프레임에 들어간 포스터**와 최소한의 메타데이터
- 저장 취소·감상 상태 변경
- 선택적 별점·한 줄 감상
- 기록이 없을 때 탐색 화면으로 연결하는 빈 상태 안내

**명칭 원칙:** 메뉴 이름은 **보관함**으로 명확하게 유지하고, 화면 부제나 영문 라벨에 `MY FILM ARCHIVE` 사용 가능. `우편함`은 사용하지 않음

### 내비게이션

**홈 / 탐색 / 보관함** 3개를 기본 메뉴로 구성합니다. 작품 상세는 카드 선택 후 이동하는 별도 화면이며 하단 탭에 넣지 않습니다.

## 5. 기능 우선순위와 범위 제한

## 6. 기술 및 데이터 설계 원칙

### 현재 프로젝트 상태 (저장소 기준)

기존 저장소는 **정적 홈 화면 프로토타입**으로 시작했습니다.

```text
ott-watch-planner/
├── README.md
├── index.html          # 홈·탐색 화면 (해시 라우팅 #/ · #/explore)
├── css/style.css       # SCENE SIDE 4색 토큰 스타일
├── js/
│   ├── data.js         # 실제 작품 26편 + 직접 정리한 시대·소재 태그
│   ├── search.js       # 제목·태그 검색과 필터
│   └── app.js          # 화면 전환, 렌더링, TMDB 포스터 불러오기
├── api/tmdb.js         # Vercel 서버리스 TMDB 프록시 (키 숨김)
└── tests/search.test.js  # node tests/search.test.js
```

### 실행 방법

- **포스터 없이 빠르게 확인:** `index.html`을 브라우저로 엽니다. API 없이 제목 플레이스홀더로 동작합니다.
- **포스터까지 확인:** [TMDB](https://www.themoviedb.org/settings/api)에서 "API 읽기 액세스 토큰"을 발급한 뒤, Vercel 프로젝트 환경 변수 `TMDB_API_KEY`에 넣고 배포하거나 `vercel dev`로 실행합니다(로컬은 `.env.local`에 `TMDB_API_KEY=...`).
- **검색 규칙 테스트:** `node tests/search.test.js`

기존 홈에는 로고, 검색 입력창, 시청 중 카드, 최근 기록, 하단 메뉴가 있습니다. **현재 검색·버튼·화면 이동이 실제 기능으로 연결되어 있다고 가정하지 않습니다.**

### 초기 구현 기술

- HTML5, CSS3, JavaScript
- 최초 MVP: 로컬 작품 데이터 및 `localStorage`
- **React/Vite/TypeScript 전환은 필수 아님.** 기존 정적 구조에서 기능 검증이 가능하면 우선 유지
- 백엔드·인증은 필요가 분명해진 다음 도입
- **작품 메타데이터 API (결정: 2026-10-22):** 포스터와 줄거리는 TMDB API로 가져옵니다. API 키는 브라우저에 노출하지 않도록 Vercel 서버리스 함수(`api/tmdb.js`)가 대신 호출하고, 키는 Vercel 환경 변수 `TMDB_API_KEY`(TMDB의 "API 읽기 액세스 토큰")에 둡니다. API를 쓸 수 없으면 포스터 없이 제목과 직접 정리한 소개로 동작합니다.
- **시대·소재 태그는 API에 의존하지 않고 직접 정리합니다.** 이 태그가 차별화 포인트이기 때문입니다.
- **유튜브 영상 시리즈:** API 키 없이 영상 ID로 공식 썸네일·임베드 플레이어를 사용합니다. 채널·재생목록 정보 자동 수집(YouTube Data API)은 필요가 확인된 뒤 검토합니다.

### 웹앱으로 시작하는 이유

- 초기에는 앱스토어 입점보다 테스트 링크를 공유하고 빠르게 수정하는 일이 중요합니다.
- 탐색·저장·간단한 기록은 네이티브 기능 없이 검증할 수 있습니다.
- 제작자의 현재 강점인 HTML·CSS·JavaScript를 활용해 기획·사용성 검증에 시간을 더 씁니다.
- 핵심 흐름이 안정화된 다음 PWA(manifest, 앱 아이콘, HTTPS, 캐싱) 설치 기능을 검토합니다.

**Flutter 등 네이티브 앱은 다음 조건이 여러 개 충족될 때 재검토합니다.**

- 사용자 테스트에서 핵심 흐름과 반복 사용 가치가 확인됐다.
- 사용자 다수가 앱스토어에서 설치 가능한 앱을 명시적으로 원한다.
- 푸시 알림·백그라운드 작업 등 웹에서 제약이 있는 기능이 핵심 가치가 됐다.
- 로그인한 사용자의 다중 기기 이용과 계정 동기화가 필요해졌다.
- 유지보수할 수 있는 개발 시간과 기술 역량이 확보됐다.

### 외부 데이터 이용 원칙

- 작품 제목·줄거리·포스터는 저작권과 API 약관을 확인한 범위에서만 사용합니다. TMDB 이용 시 약관에 따른 출처 표시를 화면에 넣습니다.
- TMDB를 상업적으로 사용하려면 별도 조건을 확인합니다.
- JustWatch 등 다른 서비스의 정보를 허가 없이 크롤링해 데이터베이스화하지 않습니다.
- OTT 제공처 정보는 국가·시점마다 달라지므로, 도입한다면 기준 국가(초기: 대한민국)와 확인 시각을 함께 관리합니다.

### 개인정보·보안 기본 원칙

- 필요한 항목만 수집하고 목적·보관 기간·삭제 경로를 안내합니다.
- 외부 사용자 데이터를 서버에 저장하게 되면 사용자별 접근 권한, 안전한 인증, 데이터 삭제, HTTPS를 갖춥니다.
- 비밀 API 키를 프런트엔드 코드나 저장소에 넣지 않습니다.

### 최소 데이터 예시

```js
// works: 작품에 대한 정적 메타데이터 예시
const works = [
  {
    id: 'work-001',
    title: '예시 작품',
    type: 'movie', // movie | drama | animation | series
    country: 'KR',
    genres: ['드라마'],
    periods: ['조선시대'],
    themes: ['궁중 문화'],
    synopsis: '실제 소개문이 아닌 테스트용 설명',
    backgroundNote: null,
    backgroundSources: [],
    poster: null,
  },
];

// userLibrary: 별도로 저장하는 사용자 상태 예시
const userLibrary = {
  'work-001': {
    status: 'want', // want | watched
    rating: null,
    review: '',
    savedAt: '2026-10-22',
  },
};
```

**설계 원칙**

- 작품 정보와 사용자의 저장·감상 기록을 분리
- `id`를 기준으로 화면 간 상태를 일관되게 유지
- 등록되지 않은 시대/소재는 임의로 추론해 검색 결과에 넣지 않음
- 작품 데이터의 국가·시대·태그·배경 정보는 검증 가능하게 관리
- 포스터·줄거리·제공처 정보는 사용 권한과 출처를 확인한 데이터만 실제 서비스에 사용
- 테스트 데이터는 테스트용임을 명확히 구분
- `localStorage`는 현재 브라우저 안에만 저장되고 기기 간 동기화되지 않는다는 한계를 UI/문서에 안내
- API 비밀 키·OTT 비밀번호는 클라이언트 코드에 넣거나 수집하지 않음

## 7. UX 및 완료 기준

### 1차 사용자 흐름

```text
홈 → 관심 주제 선택 → 탐색 결과 → 작품 상세 → 보관하기 → 보관함
                                              └→ 봤어요
```

### MVP 완료 기준

- [ ] 작품 제목을 몰라도 **주제 태그를 선택해** 검색 결과로 갈 수 있다.
- [ ] 제목 검색과 필터가 동작하며, 초기화할 수 있다.
- [ ] 작품 카드를 누르면 해당 작품 상세 화면으로 연결된다.
- [ ] 저장한 작품이 보관함에 반영되고, 저장 취소도 가능하다.
- [ ] 새로고침 후에도 저장/감상 상태가 유지된다.
- [ ] 보관함은 필름 프레임 콘셉트지만 제목·상태·조작 버튼은 분명하게 보인다.
- [ ] 작은 모바일 화면에서도 검색·저장·내비게이션이 어렵지 않다.
- [ ] 모든 버튼이 실제 동작하며, 키보드 탐색·접근 가능한 이름·대비를 고려한다.
- [ ] 데모 데이터와 미구현 기능을 실제 서비스 기능처럼 표시하지 않는다.

## 8. 개발 순서

1. **현재 코드 확인:** 파일·디자인·정적 UI 동작 확인, 재사용 가능한 부분 파악

6. **테스트 후 P1 선정:** 실제 사용성과 데이터 준비 상태를 보고 기능 확장

**중요:** 요청하지 않은 추가 기능을 한 번에 구현하지 않습니다. 핵심 사용자 흐름이 완성된 뒤 다음 단계로 진행합니다.

## 9. 사용자 테스트에서 확인할 질문

- 작품 제목을 몰라도 시대·소재 태그를 통해 흥미로운 작품을 찾을 수 있었는가?

- 감상 상태 기록이 부담 없이 간단했는가?
- 작품의 역사·문화 설명이 도움이 되는가, 혹은 탐색 속도를 떨어뜨리는가?

> 이 프로젝트는 **탐색 경험의 유용성**을 먼저 검증합니다. 브랜드 분위기는 중요한 차별화 장치이지만, 검색 편의성보다 앞서지 않습니다.

## 10. 경쟁 서비스 벤치마킹

공식 사이트·앱 설명에서 확인한 대표 기능 요약이며, 모든 국가·요금제의 기능을 완전히 비교한 것은 아닙니다. 기능은 수시로 바뀌므로 출시 전 다시 확인합니다.

| 서비스 | 참고할 점 | 단순 복제하지 않을 점 |
| --- | --- | --- |
| 키노라이츠 | 국내 OTT 통합 검색, 제공처 정보, 신작/종료 예정, 평점·리뷰, 취향 분석 | 통합 검색·평점만으로 차별화한다고 주장하지 않습니다. |
| JustWatch | 스트리밍 제공처 필터, 개인화 추천, 통합 Watchlist | 제공처 검색·찜 목록으로 직접 경쟁하지 않습니다. |
| Trakt | 시청 이력, Watchlist, 평점, 개발자 API | 모든 시청 기록을 꼼꼼히 입력하게 하지 않습니다. |
| 각 OTT 앱 | 플랫폼 자체 추천과 시청 경험 | 추천 알고리즘으로 경쟁하지 않고 **주제·맥락 기반 발견**에 집중합니다. |

'통합 검색', '찜 목록', '개인화 추천'은 독점 기능이 아닙니다. SCENE SIDE가 검증할 차별화 가설은 **시대·문화·소재 태그로 제목을 몰라도 작품을 찾을 수 있다**는 점입니다.
